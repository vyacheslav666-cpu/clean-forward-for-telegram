# Панель прогресса доставки

Единственная поверхность, по которой пользователь наблюдает автоматическую доставку. Реализация —
[`src/ui/DeliveryProgressPanel.ts`](../src/ui/DeliveryProgressPanel.ts); панель живёт в собственном
Shadow DOM, не использует Telegram selectors и рисуется только из immutable `DeliveryBatchSnapshot`,
который принадлежит `DeliveryCoordinator`. Собственного состояния доставки у неё нет: она не может
показать шаг, которого не было в snapshot.

> [!NOTE]
> В этом файле и в issues используются только синтетические имена (`Fixture recipient A`). Реальные
> названия чатов и screenshots авторизованного интерфейса в репозиторий не добавляются — см.
> [README, раздел «Безопасность»](../README.md#безопасность).

## Как выглядит выполняющийся batch

Синтетическое воспроизведение: 7 получателей, третий отправляется прямо сейчас, два предыдущих
подтверждены сервером.

```text
┌──────────────────────────────────────────────────┐
│ Отправка сообщений · v0.1.11                     │  title
│ Отправка 3 / 7                                   │  headline
│ Получатель: Fixture recipient C                  │  current
│ Отправлено: 2 · Ошибки: 0 · Неизвестно: 0        │  counts
│                                                  │
│  Fixture recipient A            Отправлено       │  list
│  Fixture recipient B            Отправлено       │
│  Fixture recipient C            Отправляем       │
│  Fixture recipient D            Ожидает          │
│  Fixture recipient E            Ожидает          │
│  Fixture recipient F            Ожидает          │
│  Fixture recipient G            Ожидает          │
│                                                  │
│ ───────────────────────────────────────────────  │
│                     Остановить после текущего    │  footer
└──────────────────────────────────────────────────┘
```

## Что откуда берётся

| Строка | Источник в snapshot | Правило |
|---|---|---|
| Заголовок | `running` + `CLEAN_FORWARD_RUNTIME_VERSION` | `Отправка сообщений · v<версия>` пока batch идёт, `Результат отправки · v<версия>` после. Версия берётся из `package.json`, поэтому заголовок — это проверка того, какой runtime реально запущен |
| Headline | `currentIndex`, `recipients.length` | `Отправка N / M` во время работы; после завершения — `Обработано: sent+failed+unknown / M` |
| Current | `safetyFailure`, `currentRecipient`, `cancelRequested`, `running` | Приоритет сверху вниз: остановка безопасности → возврат в исходный чат → текущий получатель → остановка перед следующим Send → подготовка следующего шага → операция завершена |
| Counts | `sentCount`, `failedCount`, `unknownCount` | `aria-live="polite"`; `unknown` считается отдельно от `Ошибки` и никогда не сливается с ними |
| Список | `recipients[]` | Порядок выбора получателей, он же порядок доставки. Одновременно «в работе» может быть только один |

## Метки статусов

| Статус | Метка | Цвет |
|---|---|---|
| `pending` | Ожидает | обычный |
| `navigating` | Открываем чат | обычный |
| `preparing` | Подготавливаем | обычный |
| `sending` | Отправляем | обычный |
| `sent` | Отправлено | зелёный |
| `failed` | Ошибка | красный |
| `unknown` | Результат неизвестен | красный |

`Отправлено` означает подтверждённую сервером identity нового сообщения, а не нажатый Send и не
закрытый preview. `Результат неизвестен` — терминальный статус: он останавливает batch и никогда не
попадает в повтор.

Под строкой получателя может появиться `detail` — причина отказа, красным. В debug-конфигурации
(`appConfig.debug.showDeliveryResultDialog`) добавляется техническая строка `attempts=… · retry=… ·
data-mid=…`; в production-сборке её нет.

## Кнопки

| Кнопка | Когда видна | Что делает |
|---|---|---|
| `Отмена` | batch идёт и не выполняется возврат в исходный чат | Просит остановиться перед следующим Send |
| `Остановить после текущего` | та же кнопка, когда текущий получатель уже в статусе `sending` | Та же остановка: честно называет, что текущая отправка уже необратима и будет доведена до конца |
| `Повторить оставшиеся` | batch завершён, есть `retryableCount`, и `unknownCount === 0` | Возобновляет только `pending`/`failed-before-send`; `sent` и `unknown` не повторяются |
| `Закрыть` | batch завершён | Закрывает панель |

Во время возврата в исходный чат скрыты обе кнопки: это обязательная safety-работа в `finally`,
её нельзя отменить или закрыть на середине. По той же причине `Повторить оставшиеся` прячется при
любом `unknown` — предлагать повтор там, где результат неизвестен, значит предлагать дубликат.

## Escape

Escape обрабатывается только когда панель — верхний Clean Forward overlay (`EscapeKeyLifecycle` +
проверка `isTopLevelProjectOverlay()`), и никогда не доходит до Telegram. Во время возврата в
исходный чат Escape игнорируется. Идущий batch Escape отменяет (то же, что `Отмена`), завершённый —
закрывает.

## Тема

Панель не читает настройку Telegram, а вычисляет яркость `document.body` и выбирает light/dark. Это
намеренно: тема — единственное, ради чего панель смотрит наружу, и ошибка здесь косметическая, а не
delivery-критичная.
