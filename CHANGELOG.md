# Changelog

Все заметные изменения проекта документируются в этом файле. Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), а версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [0.1.7] - 2026-08-17

### Fixed

- «Остановка безопасности: Prepared content cleanup could not be confirmed» больше не скрывает
  причину. Исходное сообщение о том, что именно не удалось подготовить, затиралось сообщением об
  уборке, и на панели оставался отказ без причины. Теперь показываются обе части;
- уборка preview имела пять независимых условий отказа и один общий `false`, поэтому определить
  причину по интерфейсу было невозможно. Каждое условие теперь называет себя;
- проверка «после закрытия preview ничего не отправляется» искала `.sending` по всему документу и
  срабатывала на посторонних исходящих сообщениях в других чатах. Проверка ограничена чатом
  получателя.

## [0.1.6] - 2026-08-17

### Fixed

- отправка картинки часто падала с «Telegram не открыл меню вложений»: ожидание было 2 секунды,
  но Telegram строит это меню только после сетевого запроса списка attach-ботов. Лимит поднят
  до 10 секунд;
- после такого отказа меню вложений оставалось открытым поверх чата и выглядело как намертво
  зависший Telegram. Причина та же, что и у контекстного меню: закрытие опиралось на
  несуществующий `.btn-menu-overlay`. Теперь меню закрывается нативно — повторным нажатием на ту
  же кнопку вложений, и закрытие отслеживается ещё две секунды на случай, когда меню
  открывается уже после отказа;
- кнопка вложений ищется по самому элементу `attach-menu-button`, без класса `attach-file`,
  который Web K больше не проставляет. Старая разметка продолжает поддерживаться.

### Added

- прямые тесты `MediaModeActivator`, у которого до этого не было ни одного собственного теста:
  он был полностью замокан в тестах composer, поэтому ни таймаут, ни оставшееся открытым меню
  не были заметны.

## [0.1.5] - 2026-08-17

Селекторы сверены с исходным кодом Telegram Web K, а не с записями ручного исследования.

### Fixed

- пункт контекстного меню не появлялся **никогда на мобильных и никогда в режиме выделения**:
  требовался селектор `.btn-menu.contextmenu.active.has-items-wrapper .btn-menu-items`, но Web K
  переносит пункты в эту обёртку только когда к меню прикреплена панель реакций, а это бывает
  лишь на десктопе и никогда при выделении. Теперь контейнером считается сама `.btn-menu`, а
  обёртка используется, если она есть;
- закрытие меню опиралось на соседний элемент `.btn-menu-overlay`, которого в текущем Web K нет —
  меню закрывается снятием класса `active` через общий обработчик. Добавлен тот же путь закрытия
  с сохранением совместимости со старой разметкой;
- кнопка в панели выделения вставлялась внутрь слота нативного Forward, а `ChatInputPlate`
  резервирует в боковом слоте место ровно под одну иконку, из-за чего кнопку зажимало. Теперь
  действие получает собственный слот `chat-input-plate-side`, который удаляется вместе с ним;
- на Apple-тач Web K открывает меню собственным long-tap таймером и не отправляет `contextmenu`,
  поэтому исходное сообщение не запоминалось. Добавлено отслеживание нажатия для touch и pen;
  для мыши поведение не изменилось.

## [0.1.4] - 2026-08-17

### Fixed

- Telegram Web K больше не зависает при загрузке: общий MutationObserver вызывал разрешение
  composer на каждой пачке мутаций, а оно доходило до `getComputedStyle` и форсировало
  синхронный пересчёт стилей всего приложения. Теперь дешёвые признаки selection mode
  проверяются первыми, и вне выделения обработка мутации не вызывает reflow;
- действие в нативном selection toolbar снова видно: shallow clone нативной кнопки Forward не
  копировал её иконку-потомка, поэтому в панели была пустая кнопка без иконки и текста.

### Added

- пункт «Отправить как новые» в нативном контекстном меню selection mode: он работает над всем
  выбранным набором, как и соседний `Forward selected`, а не над одним долгонажатым сообщением;
- поддержка обоих якорей меню (`Forward` и `Forward selected`) и переименование пункта при
  переиспользовании одного и того же меню Telegram между обычным режимом и selection mode;
- разрешение selection context при скрытом Telegram message input: в selection mode ввод
  скрывается плитой выделения, поэтому read-only поиск источника больше не требует его видимости.
  Все пути, которые пишут в composer, сохраняют строгую проверку видимости.

## [0.1.0] - 2026-08-04

### Added

- подготовка обычного текста как нового сообщения;
- подготовка одной фотографии с необязательной подписью;
- собственный выбор одного получателя из загруженных диалогов;
- multi-select UI без навигации, массовой подготовки или отправки для нескольких отмеченных строк;
- ручное подтверждение отправки через интерфейс Telegram Web K;
- автоматические тесты доменной логики, DOM-интеграции и single-recipient flow;
- production-сборка Tampermonkey userscript;
- документация по архитектуре, приватности и ограничениям.

### Security

- содержимое переноса хранится только в памяти;
- скрипт не выполняет автоматическую отправку и не обращается к сторонним сервисам;
- локальные browser profiles, cookies, session data и исследовательские артефакты исключены из Git.
- документация и fixtures используют только обезличенные синтетические значения.
