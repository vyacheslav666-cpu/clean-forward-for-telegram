# Политика безопасности

## Поддерживаемые версии

До первого стабильного релиза исправления безопасности выпускаются только для последней версии проекта.

## Сообщение об уязвимости

Не публикуйте детали уязвимости в открытом issue. После создания GitHub-репозитория используйте **Security → Report a vulnerability** (private vulnerability reporting). Если этот канал ещё не включён, свяжитесь с владельцем репозитория приватно и сообщите:

- затронутую версию;
- минимальные шаги воспроизведения;
- возможное влияние;
- предлагаемый способ исправления, если он известен.

Никогда не прикладывайте cookies, session data, browser profile, реальные сообщения, названия чатов, `peerId` или другие данные Telegram-аккаунта. Используйте только обезличенные примеры.

## Границы проекта

Clean Forward for Telegram работает внутри Telegram Web K и зависит от его DOM. Ошибка интерфейса, приводящая к подготовке неверного содержимого или получателя, считается важной: до исправления отмените preview и отключите userscript. Скрипт не должен автоматически нажимать **Send** или передавать содержимое сторонним сервисам.
